# homeplate · 产品灵魂三问

> 更新日期：2026-10-19。
> 用途：面向课程汇报，说明用户、问题和产品价值。
> 依据：[第一版范围基准](mvp.md)、[JTBD 与 Pre-mortem 分析](jtbd-premortem-analysis.md)及代码与存储迁移核对。下文区分第一版目标与现有实现，不将需求假设当作调研结论。

## 0. 汇报开场

homeplate 面向家庭和教室等空间中的家电管理：管理者拍铭牌建立档案，其他人扫码查看。第一版计划将保修计算、保养安排、主动提醒和设备相关 AI 问答放在同一个流程中，让资料容易找到，需要处理的事项有人提醒，故障出现时有初步排查依据。

## 1. 用户是谁？

**主要用户是承担设备维护任务的人，共同使用者是需要查询设备信息的人。**

| 使用者 | 典型情境 | 需要完成的任务 |
|---|---|---|
| 家庭设备管理者 | 整理家电资料、换季保养、联系售后 | 录入和修正档案，查看保修，调整计划、处理提醒或咨询故障 |
| 家庭共同使用者 | 家人想知道某台设备是否过保、何时保养 | 扫码找到设备并自行查看 |
| 教室等空间的设备负责人 | 需要统一保存所在空间的设备信息 | 管理该空间的档案与保养任务 |
| 同一空间的查看者 | 师生或员工需要了解设备情况 | 扫码查看允许公开的信息，不修改资料 |

家庭是第一批主要试用场景，教室用于验证空间共享方式；办公室可以沿用相同流程。第一版不扩展楼栋、院系、审批或工单管理。

每个人不必单独注册账号。一个空间共用一份档案，二维码提供查看入口，管理密码控制修改权限。第一版不记录具体由哪位成员操作。

上述角色按任务划分，没有经过访谈支持的年龄、职业、设备数量门槛不作为已确认画像。

## 2. 用户的痛苦是什么？

**需要处理家电问题时，资料、时间安排和处理依据没有集中在一起。**

| 需要处理的事情 | 可能遇到的困难 | 第一版要验证的问题 |
|---|---|---|
| 记录设备 | 品牌型号手抄费时，资料散在铭牌、相册和订单里 | 拍照识别加人工核对，是否更容易完成建档 |
| 查保修 | 购买日期和期限记不清，仍要找资料或问人 | 档案中的保修信息能否帮助用户查到明确的推算结果 |
| 做保养 | 忘记周期，不清楚下一次日期 | 可调整的计划和主动提醒能否帮助及时处理 |
| 共同查询 | 资料集中在某个负责人手里 | 家人或场所使用者能否通过扫码独立获取信息 |
| 排查故障 | 不知道先检查什么，普通搜索缺少设备背景 | 结合已建档设备的 AI 建议能否支持安全的初步判断 |

这些是当前的需求判断，需要通过真实任务和访谈核实。不能用未经核对的设备数量、家人访问次数或“用户一定会忘记”等说法证明痛点。

现有替代方式包括相册、纸笔、日历和直接询问。如果它们已经足够方便，本项目就需要通过更少的录入、查找和沟通步骤体现价值，而不是要求用户为使用系统额外打卡。

## 3. 产品如何解决？

**一个空间一份档案：拍照建档、扫码查询、管理保修与保养，到期主动提醒，故障可咨询 AI。**

| 处理步骤 | 第一版的产品动作 | 希望为使用者带来的帮助 |
|---|---|---|
| 先记录 | AI 识别铭牌、预填字段，人工核对；失败可手填 | 减少型号等信息的手工输入，保留纠错途径 |
| 再共享 | 保存到所属空间，生成查看二维码，修改需要管理密码 | 多人共用同一份资料，查看与修改权限分开 |
| 查清时间 | 计算保修到期日，按品类建立可调整的保养计划 | 随时查询保修状态与下一次保养日期 |
| 到期处理 | 首页突出待办，通过一个推送渠道提醒，完成保养后自动续期 | 减少对主动打开系统和人工计算周期的依赖 |
| 初步排查 | AI 结合所选设备开展文字多轮问答，提供自检与专业维修建议 | 帮助用户判断下一步，危险或不确定问题转向专业人员 |
| 长期保存 | 可靠存储、访问保护、基础备份与恢复 | 让已经录入的资料能够继续使用 |

铭牌照片不替代发票等保修凭证；保修状态取决于录入信息，不能当作厂家服务承诺。AI 提供初步参考，不保证准确诊断，也不提供维修派单服务。

### 第一版的减法边界

已确定的九个模块为：空间共享档案、AI 建档、家电档案、保修管理、保养管理、首页、基础保障、主动提醒、AI 助手。

每项只实现核心任务所需的能力：提醒先接通一个渠道，AI 先做文字和设备相关问答，共享先用空间管理密码。暂不做个人账号与成员管理、批量建档、完整维修记录和费用统计、维修交易、深色模式、小程序等扩展。具体规则和待定细节以范围基准为准。

### 当前做到哪里

现有代码已具备铭牌识别、设备增删改、保修计算、保养任务管理及续期、铭牌照片留档、首页和整站访问密码。空间二维码及权限隔离、主动提醒、AI 助手和基础备份恢复等仍需补齐。

第一版存储已由 MySQL 切换为 SQLite，无需独立数据库服务，首次启动自动建表。2026-10-19 的迁移已核对原有数据、任务和照片关联；这不代表全部首版功能已完成。

代码与迁移核对不等于当前服务在线或真实用户验收通过。旧文档中的设备数量和手机测试不作为最新结果；九模块第一版尚需整体验收。

## 4. 三问自检

| 检查项 | 当前回答 | 需要的证据 |
|---|---|---|
| 用户是否具体 | 负责维护设备的人，以及同一空间中需要查询信息的人 | 家庭实际试用和教室场景验证 |
| 问题是否具体 | 录入费时、资料分散、周期易忘、查询依赖他人、故障缺少初步依据 | 最近一次真实经历的访谈和操作观察 |
| 价值是否清楚 | 让空间内的设备资料可查、保修保养可管理、到期可提醒、故障可初步排查 | 按范围基准完成建档、扫码、保养、提醒和真实 AI 问答验收 |

真实录入至少 10 台、典型清晰铭牌单台建档 ≤30 秒等是验收目标，不能在汇报时写成已经达成的效果。用户是否继续使用，应结合实际查询、保养和故障需要观察，不能只用每日打开次数判断。

本文用于说明产品定位；后续开发与验收以 [第一版范围基准](mvp.md) 为准，取舍理由见 [减法思维说明](第一版功能取舍说明-减法思维.md)。
