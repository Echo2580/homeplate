# homeplate 后续开发路线图（ROADMAP）

> 更新日期：2026-10-19。当前第一版范围由 [docs/mvp.md](mvp.md) 唯一定义；本文负责实施顺序。主动提醒、AI 助手及空间共享均已纳入第一版。
> 原 v0.6.x 是旧 MVP 的代码起点，不代表九模块第一版已完成。当前代码变化和验证记录见 `devlog.md`，历史排期不作为完成证据。
> 存储更新（2026-10-19）：当前代码已切换为 SQLite，默认 `data/homeplate.db`，启动时自动建表；不再依赖 MySQL 服务。旧环境说明及旧排期中的 MySQL 仅供历史追溯，不能作为当前启动要求。

## 当前第一版：九个模块

空间共享档案、AI 建档、家电档案、保修管理、保养管理、首页、基础保障、主动提醒、AI 助手。

空间采用共用档案与管理密码，不要求每人一个账号。家庭、教室、办公室共用同一套流程。详细边界、延期功能、验收要求及实施前待定项统一见 `mvp.md`。

## 当前建议实施顺序

以下是开发顺序建议，不是已完成记录，也不意味着后面的模块推迟出第一版。

1. **核对既有主线与任务差距**：对照九模块基准检查 AI 建档、档案、保修、保养、首页及数据保存；保留已有可用功能。
2. **空间与权限基础**：确定管理密码恢复、查看字段及二维码更换方式，落实空间归属、数据隔离、扫码查看和管理授权。先于跨空间提醒、AI 使用铺好边界。
3. **主线适配空间**：将建档、档案、保修、保养和首页接入当前空间与查看／管理权限，完成家庭和教室场景验证。
4. **主动提醒**：先确定一个推送渠道和固定触发规则，再实现定时检查、接收目标配置、去重、直达和处理后停止。
5. **AI 助手**：确定模型与会话方式，接入当前空间设备上下文，完成真实多轮问答、自检建议、安全提示及失败处理；不依赖独立维修记录模块。
6. **第一版整体验收**：基础保障贯穿各步骤，最后集中核验手机可用性、HTTPS、权限、备份恢复及 `mvp.md` 的全部真实场景标准。

## 范围维护

- 新想法先作为候选记录，用户确认后再更新 `mvp.md`，不能直接加入开发任务。
- 最终形态设计、完整版原型及功能全量清单用于参考；不自动引入个人账号、维修记录、统计等延期功能。
- 测试记录须注明代码状态与验证条件；历史“已完成”不代替本次验收。
- 未确定的渠道、触发时间、密码恢复等细节按 `mvp.md` 第六节逐项确定，不按旧原型猜测。

- 识别供应商：.env 三变量（AI_API_BASE / AI_API_KEY / VISION_MODEL）可切换，当前 DeepSeek-flash，备选百炼 qwen-vl-plus（切回更快，配置在 .env.example 注释）

### 协作规矩（用户既定）
