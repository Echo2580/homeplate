# 第一版范围基准：九个模块

> 确认日期：2026-10-19。
> 本文记录用户确认的第一版功能范围，定义做什么、不做什么、怎样验收，是后续开发、任务拆分和验收的范围基准。
> 本文替代 2026-10-16 的三模块 MVP 范围。功能纳入范围不等于已经实现或验收通过。

## 一、定位与目标用户

**一个空间共用一份家电档案，扫码查看；拍铭牌建档，管理保修与保养，主动提醒，遇到故障可咨询 AI。**

“空间”可以是家庭、教室或办公室。第一版共用同一套家电管理流程，不扩展学校、企业的组织和审批体系。

第一批使用者是项目成员及其家庭；同时验证教室等功能场所的扫码查看场景。每个人不必注册账号，空间通过管理密码控制修改权限。

## 二、范围约定

- 第一版包含下列九个模块，不能按旧路线图将主动提醒、AI 助手或空间共享移出第一版。
- 下列“首版功能”是本轮确认的最小交付边界；不因完整原型存在更多页面而自动扩展。
- 已有可用的设备编辑、保养任务增删改等功能继续保留，不为缩小范围而删除。
- 提醒渠道、具体触发时间等未确认细节见第六节；实施对应模块前确定并回填，不能将建议当作既定需求。
- 如需增减范围，先与用户确认，再更新本文及路线图，最后安排实现。

## 三、第一版的九个模块

### 1. 空间共享档案

| 首版功能 | 最小交付边界 |
|---|---|
| 创建空间 | 设置空间名称、管理密码；家庭、教室、办公室使用相同流程 |
| 空间二维码 | 生成可分享、可打印的空间查看二维码，扫码直接查看该空间设备，无需个人注册 |
| 管理权限 | 添加、编辑、删除设备，调整或完成保养等修改操作需要管理授权；首次输入管理密码后可保持授权 |
| 密码修改与恢复 | 提供密码修改和恢复方式；更换管理密码后，原有管理授权失效 |
| 查看与管理分离 | 查看二维码不携带管理密码，也不直接授予修改权限；普通查看者不展示完整序列号等敏感资料 |
| 空间数据隔离 | 设备、任务、提醒、AI 会话和备份等数据按空间隔离；页面、接口及照片访问均执行权限检查 |

边界：不做个人账号、微信／短信登录、成员角色、邀请关系、操作人统计和家庭动态。共用管理权限不承诺识别具体操作人。

**验收：** 创建两个空间，扫码分别看到各自设备；查看者不能修改或获取管理专用资料；空间间不能越权读取或修改；管理密码可修改和恢复。

### 2. AI 建档

| 首版功能 | 最小交付边界 |
|---|---|
| 铭牌输入 | 手机拍照或从相册选择铭牌照片 |
| AI 结构化识别 | 提取品牌、型号、序列号、品类等字段，识别结果自动预填 |
| 人工核对 | 所有预填字段可修改；补充设备名称、购买日期、保修期等信息 |
| 手动兜底 | 识别失败仍可手动填写并保存，不被 AI 服务阻断 |
| 保存建档 | 确认后保存到当前空间；铭牌照片随设备留档 |

边界：一次处理一台；不做批量识别队列。AI 结果需要用户核对。

**验收：** 拍照、相册、手动填写三条路径均能建档，保存后的字段和照片归属正确；失败时给出可继续操作的提示。

### 3. 家电档案

| 首版功能 | 最小交付边界 |
|---|---|
| 列表与详情 | 查看当前空间全部设备，进入设备详情 |
| 档案字段 | 名称、品牌、型号、序列号、品类、购买日期、保修期、备注；按查看权限展示 |
| 新增、编辑、删除 | 支持日常纠错与维护；删除前二次确认，并说明关联任务和照片的处理 |
| 铭牌照片 | 长期留档并可查看原图；管理专用原图不能因公开链接绕过权限 |

边界：不做说明书 PDF、多凭证资料中心、批量操作、独立归档／换新状态流程和跨资料全局搜索。

**验收：** 新增、编辑后刷新仍保留数据；列表与详情一致；取消删除不丢数据，确认删除正确处理关联数据。

### 4. 保修管理

| 首版功能 | 最小交付边界 |
|---|---|
| 保修输入 | 填写购买日期和保修月数；品类默认值仅供参考，可人工修改 |
| 到期计算 | 自动计算保修到期日，正确处理月末和闰年日期 |
| 状态与时长 | 展示在保、90 天内到期、已过保及信息不全；展示剩余时间 |
| 首页与提醒联动 | 保修状态用于首页展示，并为主动提醒提供依据 |

边界：不做多条延保政策、自动续保和换新决策流程；特殊情况先通过编辑信息、备注处理。

**验收：** 修改购买日期或保修期后，到期日、剩余时间、首页状态同步更新；信息不全时不显示误导状态。

### 5. 保养管理

| 首版功能 | 最小交付边界 |
|---|---|
| 品类模板 | 对有模板的品类，建档后自动生成保养任务 |
| 计划展示 | 展示项目、周期、下次日期、上次完成日期及到期／逾期状态 |
| 计划调整 | 支持新增、编辑、删除任务，调整项目、周期和下次日期 |
| 完成续期 | 管理者确认完成后记录完成日期，并按周期安排下一期 |
| 提醒联动 | 到期、逾期任务进入提醒判断；完成或修改计划后同步更新提醒 |

边界：不做保养费用、前后照片、完整历次保养记录、独立任务详情页和家庭级模板编辑器。

**验收：** 自动任务与手动任务均可维护；完成后正确续期；删除、完成或调整任务后不再按旧状态催办。

### 6. 首页

| 首版功能 | 最小交付边界 |
|---|---|
| 当前空间 | 清楚展示正在查看的空间，提供管理入口 |
| 概况 | 家电总数、未来 30 天内待保养数量（含逾期）、即将过保数量 |
| 设备卡片 | 展示设备名称、品牌型号、保修状态和最近保养事项 |
| 优先处理 | 突出逾期保养、近期保养和即将过保事项，提供进入对应设备的入口 |
| 主操作与空态 | 管理者可进入添加设备；查看者不会看到可执行的修改操作；无设备时给出清楚提示 |

边界：不做独立统计图表、费用排行、设备年龄排行和复杂筛选看板；不把展示状态解释为实时物联网监测。

**验收：** 概况与真实设备、任务一致；家人或空间使用者能够自行找到需要关注的设备，并查到是否过保。

### 7. 基础保障

| 首版功能 | 最小交付边界 |
|---|---|
| 手机使用 | 手机浏览器可打开，常用窄屏和短屏下主要操作可用 |
| 访问保护 | 服务器校验空间访问与管理权限，不能只依赖前端隐藏按钮 |
| 可靠保存 | 设备、任务、照片等数据持久保存；失败可理解、可重试，避免重复操作造成数据错误 |
| 基础备份与恢复 | 能备份和恢复首版业务数据及照片，核对恢复结果；备份入口和内容限相应管理权限 |
| 运行保障 | 使用 HTTPS，具备可复现的启动、故障定位和恢复说明；真实扫码设备可访问 |

边界：先保证数据可恢复，不做 CSV／PDF 报表导出、复杂备份管理界面、原生 App 或小程序。技术基础为 FastAPI、SQLAlchemy 和 SQLite。SQLite 替代 MySQL 的独立服务，默认保存到项目 `data/homeplate.db`；首次启动自动创建文件与缺失表，照片继续保存在 `static/uploads/`，备份需覆盖两者。多空间共享仍通过同一个 Web 后端访问数据。

**验收：** 手机完成核心操作；服务重启后数据仍在；在隔离环境演练备份恢复，不清空真实业务数据；验证空间权限不会被接口或文件链接绕过。

### 8. 主动提醒

| 首版功能 | 最小交付边界 |
|---|---|
| 提醒类型 | 保修临期、保养到期和保养逾期 |
| 定时检查 | 系统主动检查应提醒事项，不依赖用户先打开首页 |
| 一个推送渠道 | 第一版接通一个真实可用的渠道；微信或邮件等具体选择实施前确定 |
| 接收目标 | 管理者为当前空间配置接收目标，无需引入个人账号体系 |
| 处理入口 | 通知可定位对应空间、设备或任务；执行修改操作仍需要管理授权 |
| 去重与停止 | 同一触发节点避免重复发送；任务完成、删除或计划调整后不再按旧状态发送 |

边界：不做多渠道切换／自动兜底、复杂提醒中心、静音、勿扰时段编辑器和保养／维修回访。具体触发时间不能从相互冲突的原型文案直接推定。

**验收：** 构造临期、到期、逾期样例，实际收到通知并能找到对应事项；重复检查不重复轰炸，处理后不再发送旧提醒；通知不泄露管理凭据。

### 9. AI 助手

| 首版功能 | 最小交付边界 |
|---|---|
| 关联设备 | 从当前空间选择已建档设备，带入品类、品牌型号和保修状态等必要信息 |
| 故障问答 | 用户以文字描述问题，AI 在当前会话内支持多轮追问 |
| 排查建议 | 给出可能原因、可进行的自检步骤，以及是否需要专业维修的建议 |
| 安全提示 | 提示断电等必要措施；危险操作或不确定问题建议联系专业人员，保内优先联系官方售后 |
| 异常处理 | 请求中有状态反馈；失败可重试，不能把固定演示回复当作真实模型结果 |
| 访问边界 | 在管理权限下使用；只能引用当前空间中所选设备的信息 |

边界：不做找师傅、派单、预约、支付、独立维修记录、对话转维修记录、故障图片诊断、长期对话档案和知识库系统。费用预估不作为首版必交付要求。

**验收：** 真实模型能结合所选设备回答并连续追问；切换设备后不混用上下文；无法判断时说明不确定性；危险故障给出停止自行处理、寻求专业帮助的建议。

## 四、明确不纳入第一版

| 功能组 | 本轮处理 |
|---|---|
| 个人账号与家庭成员协作 | 不做个人注册、微信／短信登录、成员角色、邀请关系、操作人统计和动态流 |
| 批量与资料中心 | 不做批量建档、说明书 PDF、多凭证管理和全局搜索 |
| 完整设备生命周期 | 不做独立归档恢复、换新、出售、报废及多次延保政策流程 |
| 完整服务记录 | 不做独立维修记录、完整保养历史、费用和服务账单 |
| 维修交易 | 不做师傅匹配、报修派单、预约、支付和平台售后 |
| 高级提醒 | 不做多渠道兜底、复杂提醒中心、静音、勿扰设置和回访 |
| 数据展示与外观扩展 | 不做统计图表、费用排行、设备年龄排行、深色模式和 CSV／PDF 报表 |
| 多端及组织管理 | 不做小程序、原生 App、楼栋／院系管理、审批和工单体系 |

以上为延期功能，不是永久否定。完整原型中的相关入口不要求在第一版照搬。

## 五、整体验收与完成口径

九个模块各自达到第三节验收要求后，还需完成以下真实场景验收：

1. 家庭真实录入至少 10 台电器，验证照片、字段、保修和保养计划。
2. 对典型清晰铭牌实测从拍照到建档完成的耗时，沿用 ≤30 秒目标；记录样例、网络／模型条件与失败情况，不把目标写成已达成事实。
3. 家人无需开发者代操作，即可扫码查询指定设备是否过保；管理者可以完成一次保养并看到正确续期。
4. 验证家庭和教室两个空间的二维码、查看／管理边界及数据隔离。
5. 实际验证三类主动提醒，以及关联设备的真实 AI 多轮问答。
6. 完成手机使用、重启保留和隔离环境备份恢复验证。

现有版本完成的是旧 MVP 主线，不代表本次九模块第一版已完成。开发自测、真实模型验证和用户实机验收分别留证，不能以静态原型或历史测试结果替代。

## 六、实施前需要确定的细节

以下只影响具体实现，不改变九个模块已纳入第一版的决定：

| 待定项 | 确定时点 |
|---|---|
| 主动提醒的唯一推送渠道、接收目标配置方式 | 提醒模块任务拆分前 |
| 保修提前多少天、保养何时提醒、逾期后何时再提醒 | 提醒模块任务拆分前；原型有不同口径，需要统一 |

| 扫码查看的具体公开字段与敏感字段清单 | 空间查看页实现前；铭牌原图按管理资料处理 |
| AI 服务、模型、当前会话保留方式和故障样例 | AI 助手模块设计时 |

2. `docs/ROADMAP.md` 只安排本文范围内的实施顺序，不另行改变第一版边界。
3. `docs/最终形态设计.md`、`docs/功能全量清单.md`、墨刀提示词及完整版原型是长期愿景和候选功能参考，不是第一版全部交付要求。
