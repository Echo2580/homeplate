# MVP 范围说明

> 本文档定义第一版的功能边界：**做什么、不做什么、怎么算完成**。
> 所有开发讨论以本文为准；要改范围，先改这里，再动代码。
>
> 定稿：2026-10-16

## 一句话定义

**拍一张铭牌 → 自动建档 → 打开首页，就知道"哪台保修快到期、哪台该保养"。**

## 目标用户

需要管理家电、维修记录和保修期限的普通家庭。

第一个用户就是我们自己家——每一台真实电器，都是测试数据。

## 核心闭环

**拍摄铭牌 → AI 识别型号 → 建立档案 → 自动排保修 / 保养 → 首页看板**

闭环之外的一切，本版都不做。

## 第一版做什么

### 1. 家电档案（核心）

| 能力 | 最小版本的定义 |
|---|---|
| 拍铭牌识别 | 拍照 / 上传 → 多模态大模型**一次调用**读出品牌、型号、序列号 |
| 手动兜底 | 识别结果可直接编辑——AI 只是加速器，手动输入永远可用 |
| 建档 | 用户补充：购买日期（必填）、品类（必选），备注选填 |
| 管理 | 设备卡片列表，支持新增、编辑、删除 |

### 2. 保修时钟

| 能力 | 最小版本的定义 |
|---|---|
| 到期计算 | 购买日期 + 品类默认保修期（预置表，可手动改）→ 自动算到期日 |
| 状态展示 | 三色状态：在保 / 90 天内到期 / 已过保 |
| 首页排序 | 默认按"最快到期"排序——打开就是它 |

### 3. 保养排期（轻量版）

| 能力 | 最小版本的定义 |
|---|---|
| 自动挂模板 | 按品类自动生成保养任务（见附表） |
| 展示与完成 | 显示"下次保养时间"；完成后打勾 → 自动排下一期 |
| 边界 | 本版不支持自定义周期编辑（v1.1 再做） |

## 第一版不做什么

防止范围膨胀——以下全部推迟，不要提前动：

| 砍掉 | 理由 | 计划 |
|---|---|---|
| 推送通知 | "打开就看得到"先顶上；推送需要服务器定时任务 | v1.1 |
| 维修记录 | 锦上添花，不影响闭环 | v1.1 |
| AI 维修助手 | 主流程没跑通之前不碰 | v1.2 |
| 账号体系 | 家庭共用，一个访问密码足够 | 后续 |
| 小程序 / App | 手机浏览器 Web 先跑通，最快出成果 | 后续 |

## 技术口径

- **形态**：Web，手机浏览器能开；家庭内共用部署（一台机器跑服务）
- **识别**：多模态大模型直读铭牌（一次调用出结构化结果），不搭传统 OCR 管线
- **存储**：SQLite + FastAPI
- 其余技术细节在开发阶段另行确定

## 验收标准

达成以下三条，MVP 算成功：

1. 家里真实录入 **10 台以上**电器
2. 单台设备从拍照到建档完成 **≤ 30 秒**
3. 家人（尤其是爸妈）能自己查"这台过保没"——**不来问我们**

## 开发顺序建议

1. 先跑通"拍铭牌 → 建档"闭环（最值得先验证的亮点）
2. 再加保修计算与首页看板（产品价值锚点）
3. 最后补保养排期（模板 + 打勾续期）
