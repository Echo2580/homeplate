# 交接文档：手机无法访问局域网内电脑的 Web 服务

## 问题描述

想让**手机浏览器**访问**电脑上运行**的 Web 服务（FastAPI + Uvicorn，端口 8000），用于产品验收（手机实拍建档流程）。手机访问 `http://172.24.251.35:8000` 始终失败（Edge/浏览器报"无法访问此网页"）。

## 已验证的事实（全部经过命令确认）

1. 服务状态：Uvicorn 监听 `0.0.0.0:8000`，`netstat -ano` 确认 `TCP 0.0.0.0:8000 LISTENING`（PID 为用户 PyCharm 启动的 python 进程）
2. 本机 `127.0.0.1:8000` → HTTP 200 ✓
3. 本机走局域网 IP `172.24.251.35:8000` → HTTP 200 ✓（即服务本身对局域网开放、代码无问题）
4. 电脑无线网卡（InterfaceAlias = WLAN）IP = `172.24.251.35`，网段 `172.24.x.x`
5. 防火墙：已添加入站放行规则，命令执行成功：
   ```
   netsh advfirewall firewall add rule name="homeplate-8000" dir=in action=allow protocol=TCP localport=8000
   ```
6. 手机浏览器访问 `http://172.24.251.35:8000` → 始终失败

## 环境细节（可能存在干扰因素）

- OS：Windows（中文环境），普通用户权限（涉及管理员的操作需 UAC 提权）
- 电脑上**同时存在多个虚拟网卡**（这是本机网络的复杂点）：
  | IP | 适配器 | 说明 |
  |---|---|---|
  | 198.18.0.1 | Meta | **Clash TUN 模式虚拟网卡，代理软件正在运行** |
  | 192.168.65.1 | VMware VMnet1 | |
  | 192.168.184.1 | VMware VMnet8 | |
  | 192.168.56.1 | VirtualBox Host-Only | |
  | 172.25.144.1 | vEthernet (Default Switch) | Hyper-V |
  | 172.24.251.35 | **WLAN** | 真实无线网卡，目标地址 |
- 网段 `172.24.x.x` 疑似校园网/企业网/特殊路由环境（不是家用路由常见的 192.168.1.x）
- 用户曾用浏览器直接访问 `0.0.0.0:8000`，返回 **HTTP 502**（疑似请求被 Clash 接管后代理失败，已在交接前纠正为正确地址访问）
- 手机型号/系统、手机当前 IP、手机所连 WiFi 名称：**均未提供**（关键缺失信息）

## 缺失的关键信息（诊断前建议先补齐）

1. 手机当前连接的 WiFi 名称，以及**手机自身的 IP 地址**（判断是否与电脑同网段：前两段是否同为 172.24）
2. 电脑 `ping 手机IP` 是否通（一步定位是网络层不通还是服务层不通）
3. 当前 Windows 网络位置类型（公用/专用），与防火墙规则的 profile 匹配情况
4. Clash TUN 是否接管了局域网流量（路由表中 172.24.0.0/16 的路由指向哪里）

## 既有怀疑方向（按可能性排序，欢迎推翻）

1. **手机与电脑不在同一网段/VLAN**——172.24 网段像是划分了 VLAN 的校园/企业网，同名 SSID 下不同位置可能被分到不同网段
2. **AP 隔离**——该类网络常禁止无线客户端之间互访
3. **Clash TUN 劫持**——TUN 网卡可能影响本机局域网路由
4. 防火墙规则 profile 与当前网络位置（公用/专用）不匹配
