# 基于减法思维的第一版功能取舍说明

项目：homeplate · AI 家电保养与维修助手  
日期：2026-10-19

## 一、第一版要解决什么问题

家庭中的家电通常需要使用多年，但型号、购买日期和保修期限分散在铭牌、订单或纸质单据中。需要查询时，使用者往往还要重新寻找资料；保养周期则容易依赖个人记忆。设备出现问题后，用户也需要先判断能否自行检查、是否应联系售后。

本项目第一版选择围绕这些具体任务展开：**方便地记录设备，查清保修情况，按时处理保养，遇到故障时获得初步排查建议。**

我们以家庭为主要试用场景，同时考虑教室、办公室等功能场所。它们都有“多个人使用同一批设备”的特点，因此采用“一个空间共用一份家电档案”的方式，减少每个人分别注册、重复录入的步骤。第一版只验证这种共用方式，不扩展学校或企业的组织管理业务。

## 二、怎样用减法思维筛选功能

完整版原型展示了较完整的产品设想，涉及账号、档案、保修、保养、维修、提醒、家庭协作和统计等功能。如果第一版全部实现，开发和验证工作容易分散，也难以判断用户究竟需要哪些能力。

我们根据四个问题进行筛选：

1. **是否直接服务主要任务？** 能否帮助用户完成建档、查询、保养或故障初步排查。
2. **缺少它会怎样？** 是否会让主要流程中断，或者让用户必须继续依靠人工记忆和询问。
3. **能否用更简单的方式满足？** 优先选择步骤少、依赖少、容易验证的方案。
4. **能否在第一版取得验证结果？** 能否用真实设备、手机操作和明确的完成标准检查效果。

据此，我们保留必要能力，并缩小每项能力的实现深度。例如，主动提醒先接通一个渠道；AI 助手先支持文字描述和设备相关问答；账号先采用空间共用管理权限。

## 三、第一版保留的九个模块

| 模块 | 第一版保留什么 | 保留理由 |
|---|---|---|
| 空间共享档案 | 创建空间、生成查看二维码、扫码查询、管理密码、空间数据隔离 | 让家人或同一场所的使用者快速查到同一份资料，减少个人注册和重复录入 |
| AI 建档 | 拍照或相册识别铭牌，预填信息，允许修改，失败可手动填写 | 降低初次录入成本；人工核对和手动填写保证识别失败后仍能继续 |
| 家电档案 | 设备列表、详情、新增、编辑、删除和铭牌照片留档 | 为保修计算、保养计划和 AI 问答提供一致的设备资料 |
| 保修管理 | 记录购买日期和保修期，计算到期日，展示剩余时间和状态 | 直接回答“这台设备是否还在保修期内” |
| 保养管理 | 按品类生成计划，允许调整，完成后自动安排下一期 | 将容易遗忘的周期事项变成可查看、可处理的任务 |
| 首页 | 设备概况、待保养、即将过保和优先处理事项 | 让用户进入系统后能迅速判断当前需要关注什么 |
| 基础保障 | 手机使用、访问保护、可靠保存、基础备份与恢复 | 家电资料需要长期使用，数据可靠和操作可用是前提 |
| 主动提醒 | 保修临期、保养到期和逾期提醒，先接通一个推送渠道 | 用户未必经常打开系统，提醒用于把需要处理的事项送到使用者面前 |
| AI 助手 | 关联已建档设备，支持文字多轮问答、自检步骤、专业维修建议和安全提示 | 在已有设备资料的基础上，帮助用户完成故障初步判断 |

这九项是功能分组，不对应九套独立的大系统。家电档案为其他模块提供资料，首页汇总状态，主动提醒连接到期事项，基础保障贯穿各条流程。我们通过限制各模块的内部范围控制工作量。

## 四、几项关键取舍的理由

### 1. 采用空间共享，简化账号设计

家庭成员主要需要查看同一批设备，教室使用者也存在类似需求。第一版暂不建立个人注册、成员角色、贡献排行和操作人统计，而是为每个空间建立一份档案，扫码即可查看，修改信息需要管理密码。

共享查看与管理权限仍需分开。公开张贴的二维码不能直接授予删除设备、修改保养计划等权限，敏感资料也不能全部公开。

这种方案减少了账号操作，但暂时无法准确追溯每一次操作由谁完成。第一版接受这一限制；如果后续试用发现多人追责是实际需要，再考虑个人身份体系。

### 2. 保留主动提醒，缩小提醒系统的范围

家电管理具有低频特点。如果只在首页显示到期状态，用户仍然需要记得主动打开系统。因此，主动提醒被纳入第一版，用于验证系统能否帮助用户减少遗忘。

第一版先选择一个推送渠道，覆盖保修临期、保养到期和逾期。暂不加入多渠道兜底、复杂提醒中心、静音、勿扰设置和回访。具体渠道及触发时间在实施前统一确定。

这一取舍是否有效，需要通过实际通知送达、用户能否找到对应事项，以及处理后是否停止旧提醒来验证。

### 3. 保留 AI 助手，限定为故障初步排查

铭牌识别解决录入问题，AI 助手解决使用过程中的初步咨询问题。设备已经建档后，可以将品牌、型号和保修状态作为问答背景，减少用户重复描述。

第一版只要求文字多轮问答、可进行的自检步骤、是否需要专业维修的建议和安全提示。暂不做故障图片诊断、长期对话档案、知识库、师傅匹配、预约和支付，也不将费用预估作为必交付要求。

我们保留 AI 能力，同时限制它的职责：提供参考性排查建议；对危险操作和无法确定的问题，引导用户联系专业人员。

### 4. 暂缓完整维修记录和费用统计

维修历史、凭证和费用统计具有长期价值，但需要独立记录、费用口径和更多历史数据。第一版先验证设备管理、保养提醒与 AI 咨询是否有用，暂不扩展完整维修服务流程。

因此，AI 助手可以提供建议，但暂不将对话转换为维修记录，也不生成维修账单和费用排行。

### 5. 保留数据保障，压缩展示与平台扩展

设备资料一旦丢失，会使前期录入失去价值；权限不清也会影响共享使用。因此，访问控制、可靠保存、基础备份和恢复不能作为精简对象。

深色模式、统计图表、PDF 报表、小程序和原生 App 则暂缓。第一版先集中做好手机浏览器这一种使用入口。

## 五、第一版暂缓的功能

| 暂缓内容 | 当前替代方式或暂缓原因 |
|---|---|
| 个人账号、微信／短信登录、成员管理 | 采用空间二维码查看和共用管理密码 |
| 批量建档 | 先逐台录入，验证单台流程的效率与准确性 |
| 说明书 PDF、多凭证资料中心、全局搜索 | 先保存基本档案和铭牌照片 |
| 续保政策、归档恢复及换新状态流程 | 先通过编辑保修信息和备注处理特殊情况 |
| 完整保养历史、维修记录、费用和服务账单 | 先保留当前计划、上次完成时间及自动续期 |
| 找师傅、报修派单、预约和支付 | 涉及外部服务供给与履约，超出第一版验证目标 |
| 多渠道提醒、复杂提醒设置与回访 | 先接通一个渠道和固定规则 |
| 统计图表、费用排行、深色模式、报表导出 | 暂不影响核心任务完成 |
| 小程序、原生 App、组织审批和工单 | 先验证手机 Web 和空间共享场景 |

这些功能保留在长期设想中。后续是否加入，应根据试用中出现的问题决定，而不是因为原型中存在入口就全部实现。

## 六、怎样判断这次取舍是否合理

第一版的验收将围绕真实任务开展，主要包括：

- 在家庭中真实录入至少 10 台电器，检查档案、照片、保修和保养计划是否正确。
- 对典型清晰铭牌实测建档耗时，沿用单台不超过 30 秒的目标，同时记录网络、模型条件及失败情况。
- 让家人自行扫码查询设备是否过保，让管理者完成一次保养并确认下次日期正确。
- 使用家庭和教室两个空间，验证扫码查看、管理权限及数据隔离。
- 实际验证三类主动提醒，并检查重复发送和处理后停止提醒的行为。
- 使用真实模型验证关联设备的多轮问答，检查建议是否相关、能否说明不确定性及提示必要的安全边界。
- 验证手机操作、服务重启后的数据保留，以及隔离环境中的备份恢复。

以上是计划验收目标，尚不能作为已经达成的成果。交付后还应观察用户是否会继续查询资料、响应提醒，并在访谈中了解哪些步骤麻烦、哪些功能没有实际使用。这些观察用于指导后续取舍，不将其预先写成已验证结论。

## 七、文档用途与后续安排

本次功能选择以 2026-10-19 确认的九模块范围为依据。当前已有代码覆盖旧 MVP 的主要流程，九模块第一版仍需继续完善和整体验收。

后续开发将优先补齐空间共享与权限基础，将现有档案、保修和保养流程接入空间，再完成主动提醒和 AI 助手，并按真实场景验收。实施顺序不改变九个模块均属于第一版的决定。

本文用于向老师说明取舍依据；具体功能边界、待定事项及验收要求以 [第一版范围基准](mvp.md) 为准，开发顺序见 [开发路线图](ROADMAP.md)。新增功能应先说明它解决的实际问题，再决定是否调整范围。
