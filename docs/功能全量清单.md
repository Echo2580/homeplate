# homeplate 功能全量清单（用于优先级筛选）

> 第一版范围已于 2026-10-19 确认，见 [第一版范围基准](mvp.md)。本文继续作为最终形态的候选功能池，空白优先级、原型入口和历史现状标记均不代表首版交付承诺；开发与验收以九模块基准为准。

> 来源：`完整版原型/` 全部 17 个 HTML + `docs/最终形态设计.md` + `docs/ROADMAP.md` + 现有后端 `app/`
> 整理日期：2026-10-19 ｜ 基线版本：原型 v2.0.0 / 实现 v0.6.0
> 用法：在最后一列「优先级」填 **P0**（必须上线）/ **P1**（应该做）/ **P2**（锦上添花）/ **砍**。填完直接按模块拆任务。

## 图例

**现状**
- ✅ 已实现：代码里能跑
- 🟡 部分实现：有接口没页面，或有页面没后端
- 🧩 仅原型：设计稿有，代码零
- ❌ 设计缺口：连原型都没画

**估时**（单人）
- S ≤ 0.5 天 ｜ M 1–2 天 ｜ L ≥ 3 天

# 附录 2：数据模型缺口

| 表 | 状态 | 用途 |
|---|---|---|
| `devices` | ✅ 已有 | 设备档案 |
| `maintenance_tasks` | ✅ 已有 | 保养任务（含 last_done_at） |
| `maintenance_records` | ❌ 缺 | 每次保养的时间/费用/照片/操作人 |
| `repair_records` | ❌ 缺 | 维修记录全字段 |
| `device_vouchers` | ❌ 缺 | 发票/保修卡/凭证照片 |
| `warranty_policies` | ❌ 缺 | 原始保修 + 多次延保，最新生效 |
| `families` / `members` | ❌ 缺 | 家庭与成员、角色 |
| `reminder_logs` | ❌ 缺 | 提醒生成/推送/处理回执 |
| `user_settings` | ❌ 缺 | 渠道、规则、勿扰、深色 |
| `devices.status` | ❌ 缺字段 | 在用 / 归档 / 已替换 |

> 注：`families` 一旦引入，所有业务表都要加 `family_id`。这是全库改造，建议作为独立阶段。
