本机访问自己的 WLAN 地址成功，只能证明该请求路径上的服务正常，**不能据此证明外部手机一定可以接入**。

### 3.3 抓包与有效性校验

用户先在管理员终端执行过两次 PktMon 抓包。导出文件为 0 包，第二次连已成功的网关 Ping 都未记录，因此**不能用这些空 ETL 文件证明 AP 隔离或手机没有发包**。

之后通过 Windows UAC 启动独立诊断脚本，改用实时计数，避免依赖异常的 ETL 导出：

1. 网关 ICMP 对照：WLAN 实时计数接收 2 包、发送 2 包，证明计数链路有效。
2. 清理对照筛选器，单独监视 `172.24.101.1 + TCP + 8000`，覆盖全部网络组件。
3. 用户确认在监视期间刷新手机地址 3 次，仍无法访问；工具在收到用户回复后才停止。
4. 最终匹配流量计数为 0，手机邻居状态为 `Unreachable`。

有效结论：这次没有观察到符合上述筛选条件的 TCP 流量进入电脑可观测网络栈，证据支持连接问题发生在进入 FastAPI 之前。**具体是 AP 隔离、网络访问策略、手机发送路径还是其他网络因素，仍未定案。**

所有本轮诊断会话均已停止，本轮临时筛选器已清理。没有继续禁用虚拟网卡或修改静态路由。
